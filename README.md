## 四种状态不要混成一句“跑路”

网站打不开可能来自域名失效、地区网络阻断、维护或服务器故障；暂停注册表示不接受新用户；停止服务表示既有服务不可继续；运营方失联并带来资金损失，才更接近通常所说的跑路。四种状态需要不同证据。

扬帆云当前最谨慎的公开写法是“存在社区停服报告，本站尚未独立确认”。这足以支持暂停新增付款，却不足以断言所有入口、账户和售后在所有地区都已终止。

## 建立域名时间线而不是找一个新链接

记录曾用完整域名、首次发现异常时间、DNS 结果、不同网络的 HTTP 状态、证书信息和页面内容。单台境外机器返回 200 不能证明中国各地可达；某地打不开也不能证明源站消失。至少要把“源站活着”和“目标用户能访问”分开。

若搜索到所谓新官网，应寻找旧公告或已登录面板对新域名的明确指向。仅由第三方短链、同名群组或新注册域名自称接替，不足以建立继承关系。

## 已付款用户先保存什么

保存订单号、套餐名称、金额、付款时间、支付渠道、收款主体、当时的退款条款、客服对话和异常发生时间。截图要包含页面地址和日期，但公开求助前必须遮住真实姓名、账户、订阅令牌和完整流水号。

不要反复向不明“客服”提交验证码、身份证照片、远程控制权限或新的转账。声称先付解冻费、迁移费才能退款的做法是额外风险。

## 支付申诉如何表述更有效

向支付渠道说明可核验事实：购买了什么、承诺的服务周期、从何时开始无法使用、联系商家做了什么、希望退款的未履约金额。避免只写情绪性标签；订单与服务失败时间线通常比“网上都说跑路”更有帮助。

不同渠道的争议期限和证据要求不同，应尽快在官方应用或客服电话确认。加密货币与不可逆支付通常缺少传统拒付机制，因此不应再向任何人支付所谓追回费用。

## 一套可复查的核验流程

1. **身份：**保存完整域名、公告入口、订单系统和付款主体，检查四者是否能互相指向；
2. **报价：**记录抓取日期、一次实付、周期、流量、倍率、续费与退款，不只抄月均价；
3. **软件：**从已核实帮助页或上游项目下载，写明系统、架构、版本、签名和权限；
4. **测试：**固定设备、网络、客户端、节点和时段，保留成功次数与总次数；
5. **复盘：**把事实、服务方标称、第三方说法、主观体验和未知项分栏；
6. **更新：**域名、套餐、客户端或状态变化时追加新行，保留旧快照和证据日期。

这套流程不会保证任何服务未来可用，但能减少把同名页面当官网、把年付折算当月付、把单次峰值当稳定或把推广短链当品牌认证的错误。

# 翻墙方式对比与风险

怎么翻墙、如何翻墙和 vpn翻墙这些问题，可以先分清谁提供应用、谁运营服务、谁维护配置。本文是一份只讨论概念与责任的翻墙教程，把翻墙相关的应用、订阅类服务和自建分别记录，不提供部署方法或使用效果保证。

## 比较对象先按交付内容分开

VPN 应用页面可以包含平台、设备数、协议与数据政策，订阅类服务涉及交给第三方客户端读取的配置，自建这一项则由使用者自己承担部署与维护。这几个交付对象不相同，不能只按软件图标或价格归成一件事。本文不为自建补服务端软件、命令或网络操作。

比较时用“谁作出声明、交给什么内容、哪一方负责哪部分”来组织记录。应用开发者身份是应用资料的一栏，远端服务的运营说明又是另一栏。名称相同或页面互相提到，不会替缺少的经营主体资料建立确认关系。

公开产品也不能用一个词概括全部交付。比如某页同时提供桌面应用和浏览器扩展入口，仍不代表两者覆盖范围完全一致；某页列出多个协议，也不直接回答计费、日志或系统授权。各栏目需要保留各自的问题。

本页没有一份可以证明某种方式普遍更安全、更快或适用所有设备的材料。因此比较的是公开说明的范围，不给方式排位，也不以名称取代页面记录。读不到的经营与服务内容不从行业习惯补写。

## VPN 应用需要同时读取接口和服务声明

Android 的 VpnService 为应用提供虚拟接口、地址和路由配置，以及供应用读取、写入数据包的描述符。应用再负责与远端交换数据，这是一份系统能力说明。它没有把所有使用接口的程序写成同一家服务，也没有给每款程序相同的隐私结论。

Apple NEVPNManager 的用途是创建和管理 Personal VPN 配置。官方描述的典型场景涉及不安全网络上的上网活动保护，但这句话没有提供某个具体服务的经营资料。平台 API 是程序怎样接入系统的依据，不是经营主体的证明。

[Android VpnService 官方文档](https://developer.android.com/reference/android/net/VpnService) 与 [Apple NEVPNManager 官方文档](https://developer.apple.com/documentation/networkextension/nevpnmanager) 分别指代两套文档。它们可以解释系统层的对象，却不能替产品决定是否包含服务器、怎样计费或保留哪些数据。具体承诺必须由对应产品资料单独给出。

产品页自己的声明也要留主语。Mullvad 在官方资料中作无活动日志的自述，同一资料又列付款记录、支持邮件等内容；不能只截取一句无日志便抹掉其他栏目。ExpressVPN 官方的活动和连接日志自述，同样不替其他产品承担承诺。

## 订阅类交付围绕配置输入而非应用安装

订阅这一栏在本文只讨论客户端读取配置的关系，不列商家或地址。应用安装完成与取得可读取的配置不是同一步，配置来源也不由客户端名称自动确认。本文没有取得可用于介绍任何具体订阅服务的经营资料。

HTTP CONNECT 的规范可以提供一段较具体的连接概念：代理向目标建立隧道，成功后转发两端数据，请求里包含主机和端口。这个说明来自协议，不代表某个订阅服务确实采用了它，也不提供经营者的身份。协议对象不能代答谁在运营。

[RFC 9110](https://www.rfc-editor.org/rfc/rfc9110) 指代这份规范。它给出的是隧道建立与数据转发的描述，没有列出对所有订阅服务适用的可见内容清单。本文不根据连接经过代理，就补出每项网页字段会被哪一方读取。

订阅交付与应用交付的区别可以停在这里：一个涉及交给客户端的资料，一个涉及程序本身的能力。两者可在使用过程中关联，却没有因此形成同一主体、同一政策或同一资源承诺。没有对应声明时，这些联系保持未确认。

## 数据可见性不能只用中转位置判断

TLS 1.3 的规范描述了通道建立后的机密性，数据只对通信端点可见。它还说明数据长度不会被隐藏，因而不能把加密概括为所有信息都不可见。这里采用的是协议性质，不给任何服务附加匿名性或隐藏身份的承诺。

[RFC 8446](https://www.rfc-editor.org/rfc/rfc8446) 所说明的端点，不能由本文自行等同于某个现实经营者。具体应用、远端服务以及实际连接之间的映射没有在材料中逐项给出，因此不画“所有经营者能看到什么”的统一表。协议的端点概念与品牌归属不是一个字段。

FTC 在 2018 年的提示写到，使用 VPN 应用涉及授权它接管互联网通信。这个机构提示表达权限风险，不是对每个加密会话逐字段的解密说明。权限层面的提醒与 TLS 的机密性定义需要分开读。

机构资料用 [FTC 2018 年业务博客](https://www.ftc.gov/business-guidance/blog/2018/02/market-vpn-app) 表示。它有清楚年份，也没有为本文提到的方式提供今天的行为审计；本文不会把历史提示改为某个当前产品的实际记录。能确认的权限性质和实际收集行为仍分栏保存。

## 平台规则说明应用须做到什么

Apple 的 VPN 类应用要求界面在购买或使用前披露数据项目及用途，还对数据的出售、使用、第三方披露设有限制。组织身份上架与 NEVPNManager 也是该条款的要求。它们约束应用，但不能替未读取的服务页面作声明。

Google Play 对 VpnService 也有显著披露、用户同意、商店注明及设备到端点加密等要求。仅在隐私政策、服务条款留说明，不满足其显著披露要求，政策还限制为了变现操纵其他应用的通信。条款的存在与某款应用实际做到这些要求，是不同命题。

[Apple App Store 审核指南](https://developer.apple.com/app-store/review/guidelines/) 和 [Google Play VpnService 政策](https://support.google.com/googleplay/android-developer/answer/12564964) 对应的是平台规则。本文没有执行平台审核，也没有替某个商家提交声明。因此不会写“上架等于全部行为已证实”，更不会把这份规则扩成对订阅资料的统一认证。

比较交付方式时，可把规则适用的对象写明。谈的是应用政策，就不把它作为自建或任意外部订阅的一份服务合同；谈的是产品页面，就不把产品承诺写成系统功能。适用范围不能因段落相邻而改变。

## 费用和设备限制要回到明确的方案页

产品页面可能按数据额度、设备数、计费周期分别给条件。Proton 的免费页同时写数据无上限、设备数量和随机地区条件，定价页又用 Medium 描述免费速度。本文用它说明栏目可并存，不据一个无上限措辞删除其他限制。

Windscribe 的免费额度与确认邮箱条件相连，TunnelBear 的额度带月度周期。两个例子都说明应保留原页的条件和单位，不由免费字样补出无限设备或无限期资源。本文不将它们排成价格比较，也不提供付费入口。

NordVPN 与 ExpressVPN 的价格资料还将首期和续费分开，同一产品的金额也需要保留对应期限。这里只指出字段的不同性质，不拿某个折合月额推成所有方式都逐月扣费。没有给出方案的自建一栏，也不会从商业产品价目借用金额。

这些条件回答的是具体产品怎样收费或限制使用。它们不能证明应用是否符合政策，也不能证明某个订阅服务是否属于相同主体。比较表保留“页面写了什么”，不将财务字段用作网络效果或身份判断。

## 自建这一栏只写部署维护责任

对自建，本文仅确认使用者自己承担部署与维护。所用材料没有提供可在此展开的自建来源，因此不介绍服务端、环境、端口、证书准备或具体流程，也不把其他产品的页面内容改造成部署教程。

这意味着本文不能给自建填写一个已知的运营成本、设备上限或维护难度。它们没有因“自己维护”四个字自动得到数值。没有资料的栏保持空缺，而不是用商业服务的条款或口语经验替代。

| 比较栏 | 本文能够记录的内容 | 仍需独立资料的部分 |
| --- | --- | --- |
| VPN 应用 | 平台接口、应用页和平台要求 | 具体应用的当前行为记录 |
| 订阅类服务 | 客户端读取配置的交付概念 | 具体运营者及其服务条款 |
| 自建 | 使用者承担部署维护 | 实现、成本与运行方法 |

这张表没有把资料少等同于风险高，也没有把条款多等同于结果有保证。它保留三类方式分别能说到哪里，避免一个笼统名称吞掉运营、交付和数据三个不同问题。本文也不作法律判断。

研究资料也需要保留对象。2016 年那份分析取 283 个使用 Android VPN 权限的应用，语料约为 140 万个 Google Play 应用；本文没有用样本数量推算当下产品比例，也没有把应用样本转换为外部订阅的经营记录。历史研究不能替未取得的具体服务作答。

产品的无日志自述也应保留例外。ExpressVPN 的官方页面称不记录在线活动及连接 IP，同时说明会收集部分不含用户 IP 的聚合使用数据。本文不删除后半段，也不把这个产品的自述扩为全部 VPN 应用或自建方式的共同数据条款。

这些补充并没有增加一份统一比较结论。运营者、配置交付与数据路径仍各需资料，某个栏目的原文较多也不能替其余栏目确认。本文保留未知，不以记录数量给方式排序。

## FAQ

### 这篇会教具体部署吗？

不会，自建仅写到使用者承担部署维护。所用资料没有覆盖具体实现或操作流程。

### 装了 VPN 应用就能知道谁运营服务吗？

系统接口文档不提供某个经营主体的证明。应用页面与服务声明需要各自明确身份关系。

### 配置由客户端读取，就属于客户端开发者吗？

读取能力并不能确认配置来源归属。本文没有据这层关系把两方认定为同一主体。

### 有 TLS 就代表没有任何信息可见吗？

规范明确保留数据长度可见性。通道机密性也不能被扩展成经营主体或匿名性结论。

### 商店政策能替外部订阅作保证吗？

所引条款约束它适用的应用。本文没有取得把它扩展到任意外部服务的依据。

### 免费方案的一个无上限条款能代表全部条件吗？

页面还可能同时列设备、地区或功能限制。不同栏目需要并读，不能只保留其中一项。
